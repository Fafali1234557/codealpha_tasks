# FitTrack — Fitness Tracker App (CodeAlpha Task 3)

**Flutter • Dart • Material 3 • shared_preferences**

A clean, responsive personal fitness dashboard built for the CodeAlpha App Development Internship. Log your workouts manually, review daily goals and seven-day progress, and keep an editable history of activities.

## CodeAlpha requirement coverage

| Required feature | Implementation |
|---|---|
| Track fitness data | Steps, workout duration and calories burned |
| Manual entry | Add activity type, date, steps, minutes and calories |
| Dashboard | Today's totals and progress towards three daily goals |
| Daily/weekly progress | Daily progress bars and selectable seven-day bar chart |
| Simple UI | Material 3 design, responsive cards, validation and icons |
| Data storage | JSON records stored locally using `shared_preferences` |

## Additional features

- Edit and delete previous logs (confirmation before deletion)
- Enter workouts for past dates via date picker
- Chart selector: steps, exercise minutes, or calories
- Input validation and persistence across app restarts
- Works on Flutter web (Chrome) and Android; no server needed

> **Important:** This app records only **manually supplied** steps and calories. It does not read phone sensors or estimate calories, and goals are demonstration defaults rather than personalized health advice. `shared_preferences` is suitable for a small internship prototype; production-scale fitness history would benefit from a database such as SQLite.

## Clone and run

If platform directories are missing from this source checkout, install Flutter and run `flutter create .` once inside `task3_fitness_tracker/` to generate the platform scaffolding, then run `flutter pub get`.

## Add to an existing Flutter project

This package is named `task3_fitness_tracker`. If you already created it with `flutter create task3_fitness_tracker`, **do not create it again**.

1. Back up the current working `lib/main.dart`.
2. Copy the supplied `lib/main.dart`, `test/widget_test.dart`, and `pubspec.yaml` into the matching paths of the existing Flutter project. Keep the generated `android/` and `web/` directories.
3. From the Flutter project root, run:

```powershell
flutter pub get
flutter analyze
flutter test
flutter run -d chrome
```

On an Android phone connected with USB debugging, select the device in VS Code or run `flutter devices`, then use `flutter run -d <device_id>`.

## Quick manual testing

1. Tap **Log activity** and add a walking session with 2,000 steps, 30 min, 150 kcal.
2. Confirm today's totals and progress bars update.
3. Try the **Steps**, **Minutes**, **Calories** chart filters.
4. Add a session with yesterday's date and check the seven-day chart.
5. Use the edit icon and change the workout duration.
6. Refresh Chrome (or restart the app) and confirm your activity remains.
7. Delete an activity; confirm the summary changes and deletion remains after a refresh.
8. Resize Chrome to a narrow phone-sized window and check for overflows.
